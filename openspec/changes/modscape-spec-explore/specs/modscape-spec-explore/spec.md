## ADDED Requirements

### Requirement: 曖昧な状態から探索を開始できる

スキルは要件が未確定の状態（「リファクタリングしたい」「もっとよい方法がないか」「こういう課題がある」等）でも受け付けなければならない（SHALL）。ユーザーに事前にタスクや要件を明確化することを求めてはならない（SHALL NOT）。

#### Scenario: 課題感だけで開始する

- **WHEN** ユーザーが「今こういう実装をしているが、もっとよい方法がないか」と話しかける
- **THEN** スキルは構造化された質問リストを出さずに、ユーザーの話の文脈に沿って問いかけを返す

#### Scenario: 完全に曖昧な状態で開始する

- **WHEN** ユーザーが「スキーマ周りを整理したい」とだけ言う
- **THEN** スキルはどのテーブルやどの課題に着目するかをユーザーと一緒に掘り下げる

### Requirement: modscape MCPツールでschemaを参照しながら探索する

探索中にschema情報が必要な場合、スキルは `mcp__modscape__*` ツール（またはmodscape CLI）を使って現在のschema・lineage・既存specを参照しなければならない（SHALL）。`grep` や直接ファイル読み込みでYAMLを参照してはならない（SHALL NOT）。

#### Scenario: テーブル構造を確認しながら話す

- **WHEN** ユーザーが特定のテーブルについて話す
- **THEN** スキルは `modscape table get` で現在のテーブル状態を取得し、会話の文脈として使う

#### Scenario: lineageを確認して影響範囲を議論する

- **WHEN** ユーザーがある変更の影響範囲を気にする
- **THEN** スキルは `modscape lineage list` で依存関係を確認し、影響テーブルを示しながら議論する

### Requirement: 方針が固まったら適切な次のスキルを案内する

探索の結果として変更の方針が固まった場合、スキルは変更の規模に応じて次のスキルを案内しなければならない（SHALL）。

#### Scenario: 軽微な変更と判断した場合

- **WHEN** 探索を通じてカラム追加・テーブルリネーム等の軽微な変更が方針として固まる
- **THEN** スキルは `@modscape-spec-requirements-lite` への移行を案内して終了する

#### Scenario: 新規・複雑な変更と判断した場合

- **WHEN** 探索を通じて新規パイプライン設計や複数テーブルにまたがる変更が方針として固まる
- **THEN** スキルは `@modscape-spec-requirements` への移行を案内して終了する

### Requirement: ファイルを生成せずに会話のみで完結する

このスキルは `spec.md` / `design.md` / `tasks.md` 等のファイルを生成してはならない（SHALL NOT）。探索の成果はユーザーが次のスキルへ移行することで引き継がれる。

#### Scenario: 探索完了時

- **WHEN** ユーザーが探索を終え次のスキルへ移行する
- **THEN** スキルはファイルを生成せずに案内メッセージのみを出力して終了する
