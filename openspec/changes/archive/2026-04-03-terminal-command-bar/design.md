## Context

現在の`CommandPalette.tsx`は `fixed inset-0 z-[2000] backdrop-blur-[2px]` のフルスクリーンモーダルとして実装されており、開いている間キャンバスが視認できない。内部は「pipeline mode」と「connect mode」の2つのUIモードを持ち、connect modeへの切り替えはキーボードで辿り着けない（Tabフォーカスが届かない）。

`executePipeline()`はパイプ（`|`）で区切られた複数コマンドをチェーン実行するが、この機能は実際の利用シーンでほとんど使われておらず、コマンド設計を複雑にしている。

## Goals / Non-Goals

**Goals:**
- キャンバスを常に全表示したままコマンドを入力できるUIを実現する
- ER関係・リネージ・ドメイン移動をすべてキーボードだけで完結させる
- コマンド文法をシンプルな引数ベースに統一する
- コマンド履歴（↑/↓）を実装してリピート操作を効率化する

**Non-Goals:**
- パイプライン（複数コマンドのチェーン実行）は廃止。復活させない
- マウス操作の置き換え（ターミナルバーはキーボード派の補完UIであり、マウス操作は引き続き有効）
- コマンドのスクリプト実行（バッチ処理）

## Decisions

### 1. コンソールはドラッグ可能なフローティングパネルとして実装する

```
┌─────────────────────────────────────────────────────────────┐
│                  [キャンバス - 常に完全表示]                  │
│                                                             │
│        ┌──────────────────────────────────┐               │
│        │ ≡  Console              ✕        │← ドラッグバー  │
│        ├──────────────────────────────────┤               │
│        │  /er fct_orders.▌               │               │
│        │  ────────────────────────────── │               │
│        │  fct_orders.customer_id  (FK)   │← サジェスト   │
│        │  fct_orders.amount              │               │
│        ├──────────────────────────────────┤               │
│        │  ✓ /ln stg → fct_orders         │← 履歴        │
│        └──────────────────────────────────┘               │
│                                              ↘ リサイズハンドル
└─────────────────────────────────────────────────────────────┘
```

- **開く**: `Ctrl+K`
- **閉じる**: `Esc` または `✕` ボタン
- **移動**: ドラッグバー（ヘッダー部分）をつかんでドラッグ
- **リサイズ**: 右下コーナーのハンドルをドラッグ
- デフォルト位置: 画面中央やや下、デフォルトサイズ: 380×280px
- 位置・サイズはセッション中保持（リロード時はリセット）

### 2. コマンドは `/` プレフィックスで入力する

`/` を打った瞬間にコマンド候補リストが表示される。

```
入力: /▌
┌─────────────────────────────┐
│ /t    Add table             │
│ /d    Add domain            │← コマンド候補
│ /er   ER relationship       │
│ /ln   Lineage               │
│ /mv   Move to domain        │
│ /del  Delete                │
│ /find Find and focus        │
└─────────────────────────────┘

入力: /er▌  → er にフィルタ
入力: /er fct_orders.▌  → カラム候補

```

`/` 以外の文字を入力している間はコマンド候補は出ない（引数の補完のみ）。

**なぜ `/` プレフィックスか？**: Discord/Notion/Linear のスラッシュコマンドと同じUXパターン。コマンド入力と通常テキストを明確に区別できる。

### 3. コマンド実行後のフロー

1. コマンドを入力して `Enter`
2. 実行結果を1行で履歴エリアに表示（✓ または ✗）
3. 入力欄をクリア
4. `Escape` でバーを閉じてキャンバスにフォーカスが戻る

「実行してすぐ次を入力」と「実行して閉じる」の両方をサポートする。

### 4. コマンドエグゼキューターを `executeCommand` に置き換える

`executePipeline()`（`|`分割チェーン実行）を廃止し、1コマンド1実行の `executeCommand(input: string)` に置き換える。

```ts
executeCommand(input: string): { status: 'success' | 'error', message: string }
```

パーサーは `input.split(/\s+/)` でトークン分割し、`tokens[0]` をコマンド名として分岐する。

### 5. `mv` のglobパターン

`mv fct* sales_domain` のように `*` をワイルドカードとして使える。内部は既存の `^pattern.replace(/\*/g, '.*')$` のロジクを流用する。

**なぜ `selected` キーワードを残さないか？**: UIの複数選択とターミナルバーを同時に使うシーンが限定的で、文法をシンプルに保つことを優先する。

### 6. `r`/`l`キーの廃止

`r`（ER connect mode）と `l`（lineage connect mode）はCytoscapeCanvasのkeydownハンドラから削除する。代替は `Ctrl+K` → `er` / `ln` コマンド。

`t`/`d`/`c`/`s`キー（追加系）と `Arrow`キー（パン移動）は引き続き有効。

### 7. キャンバスのノードハイライト連動

コマンド入力中、対象ノードをキャンバス上でハイライトする。

```
> er fct_orders▌   →  fct_ordersが黄色ハイライト
> mv fct*▌         →  fct_orders, fct_salesなどが黄色ハイライト
```

既存の`setHighlightedNodeIds()`をそのまま利用できる。`useEffect`でinputをwatchし、トークンをパースしてIDを抽出する。

## Risks / Trade-offs

- [リスク] 既存のCommandPaletteに依存しているキーボードショートカット（`/`キー）との競合 → `Ctrl+K` に一本化し、`/` は廃止
- [トレードオフ] `selected` キーワードの廃止により「マウス複数選択 → まとめてmv」ができなくなる → 初期バージョンでは許容。`mv`のglobパターンで代替できるケースが多い
- [リスク] `executePipeline` を参照している既存テストが壊れる → `executeCommand` への移行に合わせてテストを更新する
